# DiscussionBridge for Hugo

```sh
git clone https://github.com/DiscussionBridge/hugo-discussion-bridge.git
git -C hugo-discussion-bridge checkout --detach FULL_RELEASE_COMMIT_ID
```

Use the complete commit ID from the selected release record, or its verified
package. A branch checkout or the unchanged version label alone does not
identify local changes. See [normal installation](docs/INSTALLATION.md) for the
packaged shortcode, manifest and browser assets.

This package is the publishing and presentation adapter for Hugo.
It reads a deterministic manifest generated by Hugo, validates the entire
corpus before any request, resolves authorized Hugo pages through The Bridge,
retrieves explicitly configured From Discourse records, and atomically writes
nonsecret presentation data for Hugo's final static build.

Simple comments keep that generated, sanitized reply snapshot as an immediate
no-JavaScript and failure fallback. The packaged browser asset then refreshes
the public reply list on each page load using credential-free Discourse JSON,
no cookies, exact-origin checks, a 512 KiB response limit, batches of at most
20, and a maximum of 50 replies. The first five are shown immediately and the
remainder use a native **Show more comments** disclosure. The forum must allow
the exact Hugo site origin through its CORS setting.

The connection secret is read from a protected file. It is never written to
the Hugo data directory, generated HTML, browser JavaScript, logs or errors.

New From native pages require both their source binding's materialization grant
and a local `DISCUSSIONBRIDGE_HUGO_NATIVE_SHORTCODE` choice. Omission or `none`
creates no shortcode-dependent page or consumer integration. Existing owned
pages retain their working body/handler on an upgrade without a new selector.

Presentation manifests use the public modes `simple`, `full`, and
`interactive`. Only these canonical presentation modes are accepted. Unsupported
modes fail closed; no aliases or saved-value conversion are provided.

```text
discussionbridge-hugo prepare \
  --manifest public/discussionbridge-manifest.json \
  --output data/discussionbridge.json \
  --state .discussionbridge/hugo-publication-state.json
```

Required environment variables are `DISCUSSIONBRIDGE_SERVER_URL`,
`DISCUSSIONBRIDGE_CONNECTION_ID`, and
`DISCUSSIONBRIDGE_CONNECTION_SECRET_FILE`. Optional
`DISCUSSIONBRIDGE_LANE` selects the connection lane.

The state file is an atomic, secret-free operational ledger. It preserves the
stable external identity and correlation across an interrupted request and
records attempt count, outcome, retry/reconciliation status, and resolved
resource/topic identity. A later exact build can retry without losing what the
previous build attempted. A renewable filesystem lease excludes overlapping
live builds. If its owner is terminated, a later build reclaims the abandoned
lease after the bounded stale interval and retries the same recorded identity
and correlation. Inspect its bounded operator summary with:

```text
discussionbridge-hugo publication-status \
  --state .discussionbridge/hugo-publication-state.json
```

An operator may explicitly authorize The Bridge to create or update a native
Hugo content record. Presentation-only bindings are ignored. The trusted build
runs:

```text
discussionbridge-hugo sync-publications \
  --content-dir content \
  --site-url https://hugo.example.com/
```

The command validates the source topic/revision/author, exact Hugo destination,
stable resource identity, and native-materialization authority before writing
`content/discussionbridge/<slug>.md` atomically. The generated content record
uses the ordinary authenticated From Discourse build path for its bounded,
sanitized body and discussion. Exact retries are unchanged, identity collisions
fail closed, and no secret enters Hugo content or public output.

Existing native files must carry actual generated TOML front matter with the
native-publication flag and exact resource/topic identities. A marker in article
text, an empty file or a linked path cannot authorize replacement. Synchronization
preserves custom front matter, selected presentation and the full body. On a
changed source edition (or legacy revision), it updates source-managed title,
author, forum name and dates. `date` uses source creation when supplied;
`lastmod` uses source update time. Saved managed values detect later local edits
and return record-specific attention rather than overwrite those edits. First
claims are exclusive and concurrent writes use a lease. A missing edition keeps
the legacy revision path; malformed supplied editions are rejected.

From Discourse remains a direction. `discussionbridge_presentation_mode` is the
separate native Simple/Full/Interactive choice consumed by the selected shortcode.
An existing explicit selection survives source updates; a new explicit binding
selection is recorded when a native page is created. Otherwise the selected site's
presentation parameter applies, with legacy Interactive retained when absent.

The optional packaged manifest excludes draft, future and expired pages even
when a Hugo preview build includes them. Operator-owned manifests must apply the
same native publication eligibility before invoking the adapter.
